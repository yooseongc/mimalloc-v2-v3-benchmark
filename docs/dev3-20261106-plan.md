# dev3 d6716d33 변경 직접 측정

Experiment: dev3-20261106-v1. Design status: Draft before pilot.

2026-11-06 사용자가 설계·구현·측정·분석을 승인했다. 기존 결과는 보존하며
이번 질문은 마지막 비교 버전 v3.6.1 이후 변경의 관찰 가능한 영향이다.
과거 모든 버전의 결과를 재사용하거나 이번 결과와 합치지 않는다.

## 고정 대상과 가설

- v3.6.1: 56dc5eb80145f9a3ba7ca23d47c6a248b9d8586c
- dev3-d6716d33: d6716d33671c2f621b87be3c7ac016c6ba6b3c94
- upstream: https://github.com/microsoft/mimalloc

remote-free 회수의 CAS loop→atomic AND 변경은 비용에 영향을 줄 수 있다.
프로세스 상태와 스레드 초기화 변경은 시작/종료 비용 및 잔류 RSS에 영향을 줄 수 있다.
방향은 사전에 예측하지 않는다. 통합 snapshot 비교로 개별 커밋의 인과는 입증하지 않는다.

## 환경과 통제

기존 Rocky 8 이미지 sha256:73353c7a70d01f098f4adc96480273ce5d5b295bea3733c1f2faac2017e05877.
동일 GCC Release -O3 -DNDEBUG, MI_SECURE=OFF, upstream 수정 없음.
MTE/PAC 기본 OFF를 캐시로 확인한다. x86-64이므로 ARM 하드웨어 기능은 범위 밖이다.
LD_PRELOAD와 공통 실행파일, 고정 cpuset 0,2,4,6,8,10 / node 0, quota 없음,
컨테이너 메모리 상한 4 GiB, swap 금지, network none. THP는 현재 madvise 유지.
NUMA 메모리 정책은 cpuset-mems만 적용하며 명시적 mbind는 하지 않는다.
소스/실행파일/라이브러리/실행기 hash, build cache, 환경, raw JSON을 별도 보존한다.
WSL2 host 부하·주파수 및 별도 상주 컨테이너는 미통제다.

## 질문별 측정

1. 활성 concurrent.cpp: 64/1024/4096 B × 1/2 producer-consumer 쌍,
   128 MiB 생존 상한. 전체 쓰기·검증·256객체 인계 포함. 6조건×2버전×5회=60.
   pilot 각 조건 1 GiB, 가장 빠른 속도×5초를 512객체 배수로 올림, 최소 1 GiB.
   elapsed, worker CPU, RSS peak/완료/idle 1초, faults, checksum 수집.
2. 활성 lifecycle.cpp: 4 KiB×32768개=128 MiB. 같은/다른 스레드 해제,
   할당·쓰기·절반/전체 해제·idle 5초·재할당. 2조건×2버전×5회=20.
   별도 강제 collect 각 1회=4. malloc/free와 쓰기 단계 비용 분리.
3. 새 thread_lifecycle.cpp: worker를 반복 생성·join. empty control,
   local(스레드가 1024개 할당/해제 후 종료), remote_exit(할당 후 종료하고
   controller가 해제), 크기 64/4096 B. worker CPU0, controller CPU2.
   warm-up 20 cycles, pilot 200 cycles, 가장 빠른 버전 기준 3초 목표,
   최소 200 / 최대 20000 cycles. 5조건×2버전×5회=50.
   첫 명시적 malloc 시간 합계, 총 elapsed/CPU, faults, peak/완료/idle RSS,
   개수·checksum·CPU pinning 검증. empty는 thread/harness 대조군이며 비용을 빼지 않는다.
   pthread 런타임 내부 allocation과 thread 종료 비용도 총시간에 포함된다.
