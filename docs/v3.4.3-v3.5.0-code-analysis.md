# mimalloc v3.4.3 to v3.5.0 code-level analysis

Analysis status: Preliminary causal analysis; static diff confirmed, causal ablation not executed

## Scope

This note connects the frozen r25 observations to allocator changes between:

* v3.4.3: `152fbf2634aeafca3774df791b0a77683035f076`
* v3.5.0: `18b08671c9302247bfb682286e6bf3cc1773f801`

The interval is not a small patch: it changes the page/free fast path, arena and
pagemap implementation, and abandoned-page lifecycle. Consequently, a source
diff can identify plausible mechanisms, but it cannot by itself assign a
measured percentage to an individual commit.

## r25 observations to explain

Under the fixed r25 harness, v3.5.0/v3.4.3 median throughput was 1.0035 for
local fixed 64 B at eight threads, 1.0080 for local mixed-wide at one thread,
and 1.0198 for local mixed-wide at eight threads. The corresponding remote-free
ratios were 0.9139 for fixed 64 B and 0.9354 for mixed-wide at 4:4.

The latency companion measured throughput ratios of 1.0137 and 1.0395 but p99
ratios of 1.4210 and 1.0654 for the allocator and service pipelines. The 512 MiB
burst experiment found essentially equal post-free/idle RSS for v3.5.0 and
v3.4.3. These measurements do not establish superior memory return in v3.5.0.

## Candidate mechanisms

| Observation | Relevant change | Confidence |
|---|---|---|
| Small local-throughput improvement | `e927d7b0` reorganizes `mi_page_t` around malloc/free access and simplifies the local-free update; `82fd55ff` aligns page metadata for faster free | Medium-high mechanistic fit |
| Lower remote-free throughput and higher tail latency | `53b364da` changes reabandon handling when the original thread heap is uninitialized; the pagemap and atomic arena bitmap paths also changed | Medium; requires ablation |
| More retained but potentially steadier current RSS in some core workloads | `2dd48f1c` permits up to three retired empty pages per size queue instead of effectively retaining only the sole remaining page | High mechanistic fit, magnitude unproven |
| Longer retention around thread abandonment | `a89f12bf` stops arena collection on `MI_ABANDON`, changes the default `arena_purge_mult` from 1 to 4, and tightens purge-expiry handling | High policy relevance; workload activation unproven |
| Free/page lookup behavior changes | `d63979ae` refactors the two-level pagemap; `6f5bcfd7` and related commits change atomic bit find-and-clear behavior | Medium-low attribution without profiling |

### Page and free fast path

Commit `e927d7b0` places frequently accessed page fields, including `free` and
`used`, together and changes the local-free sequence to calculate and store the
new used count directly. `82fd55ff` further changes page-metadata alignment and
lookup. Fewer dependent operations and better cache locality are plausible
explanations for the small local-workload gain. This is an inference consistent
with r25, not a measured per-commit effect.

### Retired pages and RSS

Commit `2dd48f1c` introduces a maximum of three retained retired pages per size
class and scans those retired entries before collection. Keeping more reusable
empty pages can reduce page acquisition churn while increasing allocator-held
memory. It also provides a direct mechanism for a higher but less variable
current RSS. The r25 core RSS field is a point-in-time/current-RSS observation,
not a reliable process high-water mark, so it must not be described as true
peak RSS.

### Abandon, reabandon, and purge

Commit `53b364da` allows pages to be reabandoned even when their associated
thread heap is no longer initialized. This changes the state transitions and
bookkeeping reached by cross-thread frees after thread-lifecycle changes. It is
a plausible source of additional slow-path or atomic work, but static analysis
does not determine whether it caused the measured remote-free regression.

Commit `a89f12bf` avoids arena collection while abandoning a thread heap and
changes purge scheduling defaults. These changes can retain reusable memory
longer in thread-churn or abandonment-heavy workloads. They do not conflict
with the r25 burst result: the burst arm used a different lifecycle and, in the
normalized arm, explicitly set `MIMALLOC_PURGE_DELAY=1000`.

### Pagemap and arena atomics

The v3.5.0 interval also refactors the two-level pagemap used to map an address
back to page metadata and modifies optimistic atomic bitmap allocation. These
changes can affect both fast-path lookup and contention. The direction and size
of their effect cannot be separated from the other changes with the current
r25 binaries.

## Supported conclusion

The most accurate interpretation is that v3.5.0 trades some remote-free and
tail-latency behavior for fast-path and reuse-policy changes. It may retain more
reusable memory in particular allocator states, but r25 does not show that it
returns freed memory to the OS better than v3.4.3. "More predictable" is only
supported for the specific current-RSS measurements that showed lower
variation; it is not a general allocator-wide guarantee.

## Experiment needed for causal proof

Keep the r25 benchmark binary, plans, seeds, CPU placement, runtime policy, and
validity rules fixed, then build patch-stack variants that independently revert
or restore:

1. `2dd48f1c` retired-page retention;
2. `a89f12bf` abandon/purge behavior;
3. `53b364da` reabandon behavior;
4. `e927d7b0` and `82fd55ff` page/free layout;
5. `d63979ae` pagemap changes;
6. the atomic bitmap changes including `6f5bcfd7`.

Run matched randomized repetitions of the local, remote-free, latency,
thread-churn, and memory-return subsets. Add allocator diagnostic counters for
retired, abandoned, reabandoned, and purged pages in separate non-primary runs.
Only those ablations can convert the candidate mechanisms above into causal
attribution.
