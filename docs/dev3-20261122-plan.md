# dev3 처리량과 메모리 반환 실험

v3.7.0 (1ed67b5156a763441d2ec3c20221a7b3cd866129) 및 2026-11-22에 조회한 dev3 (15d1247d63b94fef02e508a8feffead8d7ac300c)를 각각 MI_SECURE OFF/ON 및 MI_ENABLE_LARGE_PAGES 0/1로 교차 빌드한다. 내부 페이지의 크기별 효과와 보안 설정에 따른 처리 비용이 서로 영향을 줄 수 있다. OS THP 정책은 유지한다. MTE/PAC는 OFF, 런타임 옵션은 upstream 기본값이다.

* Rocky 8 기존 이미지, 네트워크 차단, 메모리 6 GiB, swap 여유 0, cpuset 0,2,4,6,8,10 및 node 0을 사용한다. 동일 workload 실행 파일에 프로필별 공유 라이브러리를 주입한다.
* 두 생산자·소비자 쌍에서 4/64/256 KiB를 full-write 후 인계한다. 생존 상한 128 MiB, 배치 256 KiB. 256 MiB smoke 및 1 GiB pilot 후 크기별 가장 빠른 pilot의 2초 처리량을 GiB 단위로 올림한다. 처리 바이트는 같은 크기의 모든 프로필에 동일하게 적용한다. 미리 채운 객체도 소비량에 포함한다.
* 스레드 효과를 분리하기 위해 4 KiB × 32768개를 할당·기록한 뒤, 할당자 또는 별도 스레드가 같은 순서로 해제하는 lifecycle을 비교한다. 두 스레드는 계속 살아 있고 1초 유휴 뒤 할당자가 재할당한다. free_half와 free_rest의 worker 시간 합계, RSS high-water mark, free_rest 직후 및 1초 시점의 smaps_rollup RSS를 기록한다.
* smoke/pilot 후 작업량과 실행 순서를 plan.json에 동결한다. 각 반복 안에서 모든 조건을 seed 20261122로 섞고 3회 순차 실행한다. checksum, 실제 library·worker 배치, live count, swap 및 throttling은 기존 controller로 검증한다. 결과는 중앙값과 범위로 기술한다. 공유 호스트 부하와 클럭은 통제되지 않으며 작은 효과의 통계적 유의성을 판정하지 않는다.
